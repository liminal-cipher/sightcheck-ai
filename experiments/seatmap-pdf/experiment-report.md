# 좌석 배치도 판독 실험

국립아시아문화전당(ACC) 극장 1~3의 공식 좌석 배치도에서 좌석마다 "구역·행·번호와 도면 위 위치"를 자동으로 뽑을 수 있는지 확인한 실험 기록이다. 재현 명령은 [실험 가이드](experiment-guide.md)에, 결과를 보기 전에 고정한 API 실험 계획은 [`api-experiment-plan.md`](api-experiment-plan.md)에 있다. 원본 PDF·JPEG, 판독 결과, 사람 정답은 저장소에 넣지 않았다. 이 문서에는 집계와 한계만 적는다.

## 한눈에 보기 (2026-11-20 기준)

| 대상 | 방법 | 결과 |
| --- | --- | --- |
| 극장 1 PDF 7종, 좌석 3,760개 | PDF에 들어 있는 텍스트를 블록에 연결 | 3,760개 모두 연결. 사용자가 블록별 색상 이미지로 전수 확인 |
| 극장 2·3 JPEG, 회색 좌석 칸 750개 | 칸 위치는 CV, 글자는 Claude Sonnet 5.5가 판독 | 750칸 모두 판독($4.56). 사람 정답 98칸 모두 일치. 구조 검사 경고 0개. OCR과 비교한 568칸에서 불일치 0개 |
| 극장 2·3 파란 휠체어 영역 8개 | 없음 | 판독·검사하지 않음 |

- 칸 위치(CV)와 좌석 수는 도면 범례와 맞는다. 극장 2는 506석(일반 466 + OP 40), 극장 3은 244석이다.
- "경고 0개"는 구조상 모순이 없다는 뜻이다. 750칸이 모두 맞는다는 보증은 아니다. 근거와 한계는 아래에 적었다.

## 용어와 숫자

- **750칸**: 극장 2(506)와 극장 3(244)의 회색 좌석 칸 전부다. 파란 휠체어 영역은 범례 좌석 수에서도 빠져 있어 포함하지 않는다.
- **표본 209개**: 750칸 중 회색 칸 201개와 파란 영역 8개(극장 2 여섯, 극장 3 둘)다. 아래 규칙으로 골랐고, 개수는 규칙을 적용한 결과다.
  1. 칸을 높이별 가로 띠로 나눈다(극장 2는 20개, 극장 3은 12개).
  2. 띠 안에서 OCR 결과 종류(일반석, BOX-1, BOX-2, 번호 불확실, 행·구역 미해결)별로 묶는다.
  3. 묶음마다 가운데에 가장 가까운 칸, 좌우·상하 끝, 네 모서리 쪽 칸을 고른다.
  4. 파란 영역은 모두 넣는다.
- **OCR이 어려워한 칸**: Tesseract(로컬, 영어 모델)가 준 신뢰도 점수로 실험 코드가 판정했다.
  - "번호 불확실": 칸 안 글자가 1~3자리 숫자가 아니거나, 신뢰도가 60 미만이거나, 두 덩어리 이상으로 읽힌 칸이다.
  - "행·구역 미해결": 번호는 읽었지만 같은 가로줄의 행 라벨을 신뢰도 60 이상으로 찾지 못했거나, 서로 다른 행 글자가 나온 칸이다.
- **표본에 어려운 칸이 많다**: 회색 칸 기준으로 번호 불확실 칸은 750칸 중 65개 가운데 63개, BOX석은 27개 모두가 표본에 들어갔다. 일반석은 541개 중 90개(17%)만 들어갔다. 그래서 표본 점수는 어려운 시험지 점수에 가깝다.
- **사람 정답 106개**:

  | 이름 | 개수 | 만든 방법 | 쓰임 |
  | --- | ---: | --- | --- |
  | 블라인드 | 70 (30 + 40) | 모델·OCR 답을 보지 않고 표기 | 모델 비교와 선택. 고르는 데 썼으므로 검증(validation) 데이터에 가깝다 |
  | 확인 | 36 | Opus·OCR 답을 보면서 판정 | 참고용. 공정한 채점에는 쓰지 않음 |

  표본 중 정답이 없는 103개는 남겨 두었다. 프롬프트를 고치면 이 중에서 새 블라인드 표본(시험 데이터)을 만든다.

## 현재 한계와 다음 할 일

- **정확도의 근거**: 블라인드 70개를 모두 맞혀도 정확도의 단측 95% 하한은 약 96%다. 표본이 목적 표집이라 도면 전체 정확도도 아니다. 750칸의 근거는 사람 정답 98칸 일치, 구조 검사 경고 0개, OCR과 불일치 0개를 합친 것이다.
- **검사기의 전제**: 행마다 번호가 한 방향으로 이어지고, 행 글자가 위에서 아래로 순서대로라는 전제는 이 두 극장에서만 확인했다. 한 행 전체를 같은 방식으로 잘못 읽는 체계적 오류는 측정하지 않았다.
- **휠체어 영역**: 파란 영역 8개는 750칸 판독과 구조 검사에서 빠져 있다(11-14 Opus 서브에이전트만 읽었다). 극장 2 휠체어석은 사람이 개별 좌석으로 확인했다(11-14 확인 36개). 그러나 지금 프롬프트의 휠체어 설명이 번호가 있는 휠체어 칸을 헷갈리게 할 수 있다. 문구를 고치려면 남겨 둔 103개에서 새 블라인드 표본이 필요하다.
- **AI 의존도**: 지금 판독은 Claude API에 의존한다. OCR은 Tesseract 기본 설정만 써 봤다. 설정 조정이나 다른 OCR 엔진(무료·클라우드)은 시험하지 않았다. Sonnet 750칸 판독은 OCR을 개선할 때 비교 기준으로 쓸 수 있다. 다만 정답은 아니므로 채점은 사람 정답으로 한다.
- **범위 밖**: 다른 공연장, 실제 좌석 중심·거리·높이, 제품 운영자 화면 연동(검사기의 JS 이식 포함)은 하지 않았다. 픽셀이나 PDF 좌표를 미터로 바꾸지 않는다.
- **자료와 라이선스**:
  - 공식 웹사이트에 공개된 PDF라도 재배포나 학습 허용이 확인된 것은 아니다. 로컬 분석에만 쓴다.
  - 극장 2·3 도면 이미지는 사용자 승인 아래 Anthropic API로 보냈다.
  - PyMuPDF는 AGPL/상용 라이선스라 비공개 상용 제품에 넣기 전에 검토가 필요하다.

## 상세 기록

### 2026-10-20 PDF 텍스트 추출 baseline

대상은 극장 1의 공식 좌석배치도 PDF 7개다. 좌석 번호가 PDF 텍스트로 들어 있는 경우, OCR이나 외부 AI 없이 블록·행·번호와 **PDF 문서상 텍스트 위치**를 구조화할 수 있는지 확인했다. 실제 좌석 중심, 무대와의 거리, 축척, 높이, 3D 시야는 추정하지 않는다. 범위는 단일 페이지, 벡터 표 경계선, 좌석 그리드 위에 수평 블록 라벨이 있는 배치도다. 블록이 불분명하면 억지로 추정하지 않고 미매칭으로 남긴다.

환경은 Python 3.13.5, PyMuPDF 1.26.7이다. 종료 코드 0은 자동 무결성 검사 통과를 뜻할 뿐 좌석별 정답 검증이 아니다. 아래 수는 기계적 후보 수이며, 블록 연결의 정확성은 11-14 전수 확인에서 따로 확인했다.

| 배치 형태 | 문서 표기 좌석 수 | PDF 좌석 텍스트 | 블록 연결 후보 | 미매칭 | 자동 검사 |
| --- | ---: | ---: | ---: | ---: | --- |
| 기본 프로시니엄 | 608 | 608 | 608 | 0 | 통과 |
| 3분할(小) 208석 | 208 | 208 | 208 | 0 | 통과 |
| 3분할(小) 224석 | 224 | 224 | 224 | 0 | 통과 |
| 3분할(大) 384석 | 384 | 384 | 384 | 0 | 통과 |
| 돌출형 | 832 | 832 | 608 | 224 | 실패 |
| 로드형 | 560 | 560 | 0 | 560 | 실패 |
| 아레나형 | 944 | 944 | 608 | 336 | 실패 |

- 기본 프로시니엄은 A~J블록 각 56석과 FOH 48석이다. 208석 배치는 A·B 각 56석, C·D 각 48석이다. 208석과 224석을 비교하면 208석의 C블록 6·7행 5~8번과 D블록 6·7행 1~4번이 빠져 16석 차이가 난다. 두 PDF에 표시된 좌석의 비교이며 실제 설치 상태의 증거는 아니다.
- 실패한 세 배치에는 무대 측면·후면 좌석과 수직이거나 다른 위치에 있는 블록 라벨이 있다. 당시 코드는 수평 라벨 바로 아래의 표 상단 선분만 찾았다. 이 문제는 10-23 개선으로 해결했다.
- 합성 PDF 기반 단위 테스트 4개가 통과했다.

개선 방식은 서로 닿는 벡터 경계를 묶고, 텍스트 방향에 맞는 인접 경계의 범위로 블록을 연결한다. 무대 측면의 회전 라벨과 아레나 후면의 아래쪽 라벨을 처리한다. 기존에 연결된 모든 좌석 ID와 반올림한 텍스트 중심 좌표가 유지됐다. 파일명별 정답표나 공연장 고정 좌표는 쓰지 않는다. 임의 각도 회전, 끊어진 선, 복잡하게 공유된 경계는 여전히 한계다.

**JPEG 첫 CV·OCR 결과**

두 원본은 CMYK JPEG다. 극장 2는 1754×2550 px, 극장 3은 1754×2480 px이며 작업용 RGB 사본을 썼다.

| 자료 | 회색 도형 후보 | 번호 OCR 채택 | 좌석 ID 연결 후보 | 미매칭 도형 | 파란 영역 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 극장 2 | 506 | 465 | 366 | 140 | 6 |
| 극장 3 | 244 | 220 | 202 | 42 | 2 |

- 칸 찾기는 OpenCV의 중성 회색 마스크, 윤곽선, 대표 사각형 크기를 쓴다.
- 번호는 확대·반전한 칸별 조각을 로컬 영어 OCR로 읽는다. 같은 행 양쪽 라벨이 일치할 때만 행을 연결한다. BOX 영역은 연속된 세로 좌석열로 제한한다.
- 초기 구현에서 BOX 연결이 아래층까지 이어지는 문제가 있어 간격으로 범위를 제한했고 회귀 테스트로 남겼다.
- 일부 6·9, I행, 극장 2의 O·R행과 OP 라벨이 미해결로 남았다. 전체 페이지 OCR은 인접 숫자를 긴 문자열로 합치기도 한다.
- 극장 2 범례는 일반판매석 466, OP석 40, 휠체어석 6이다. 극장 3은 일반판매석 244, 휠체어석 4다. 극장 3의 파란 영역 2개를 범례에 맞춰 4개로 나누지 않았다.

사람 검토용 표본 550개(PDF 341, JPEG 209)를 이 날 만들었다(선정 규칙은 "용어와 숫자"). 이후 PDF 341개는 11-14 전수 확인으로 대신했다. JPEG 209개는 그중 106개에 사람 정답이 생겼다. 원래 검토 화면의 도형·위치 오차 항목은 채우지 않았으므로 CV 검출 재현율과 위치 오차는 측정하지 않았다. 합성 PDF·이미지·평가 테스트 24개가 통과했다.

### 2026-11-14 PDF 블록 연결 전수 확인

- 요청 크기 때문에 Batch 6개로 나눠 보냈다.
