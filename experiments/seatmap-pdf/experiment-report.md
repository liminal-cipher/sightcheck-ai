# Seat Map PDF Extraction Spike

아래 초기 기록은 2026-10-20 baseline이다. PDF 레이아웃 개선과 JPEG CV·OCR 후속 결과는 문서 하단의 **2026-10-23 후속 실험**에 기록했다. 재현 명령과 검토 절차는 [실험 가이드](experiment-guide.md)를 참고한다.

실행일: 2026-10-20 (KST). 대상은 국립아시아문화전당 극장 1의 사용자 제공 공식 좌석배치도 PDF 7개다. 원본 PDF·추출 JSON·미리보기 이미지는 저장소에 넣지 않는다.

## 목적과 범위

좌석 번호가 PDF 텍스트로 제공되는 경우, OCR이나 외부 AI API 없이 블록·행·번호와 **PDF 문서상 텍스트 위치**를 구조화할 수 있는지 검증한다. 실제 좌석 중심, 무대와의 거리, 축척, 높이 또는 3D 시야를 자동 추정하지 않는다.

이번 코드는 **단일 페이지, 벡터 표 경계선, 수평 블록 라벨이 좌석 그리드 위에 있는 배치도**에 한정된 초기 baseline이다. 지원 여부가 불분명하면 블록을 억지로 추정하지 않고 미매칭 후보를 기록한다.

## 실행

Python 3.10 이상 환경에서:

~~~powershell
python -m pip install -r experiments/seatmap-pdf/requirements.txt
python experiments/seatmap-pdf/extract_seats.py "C:\path\to\프로시니엄형 - 608석(기본).pdf" --output-dir experiments/seatmap-pdf/output
python experiments/seatmap-pdf/extract_seats.py "C:\path\to\3분할(小) - 208석.pdf" --output-dir experiments/seatmap-pdf/output
python -m unittest discover -s experiments/seatmap-pdf -p "test_*.py" -v
~~~

출력 경로에는 원본 PDF의 파일명에 대응하는 JSON과 검토용 PNG가 생긴다. PDF 파일 자체는 변경되지 않는다. JSON은 블록·행·번호·블록 포함 좌석 ID·문자 bbox·문자 중심(PDF pt)·미검토 상태를 기록한다.

종료 코드 0은 **자동 무결성 검사 통과**를 뜻할 뿐, 좌석별 정답 검증이나 현장 검수를 의미하지 않는다. 미매칭·중복·표기 좌석 수 불일치 또는 블록 경계 추출 실패 시 종료 코드 2를 반환한다.

## 로컬 실행에서 확인한 결과

환경: Python 3.13.5, PyMuPDF 1.26.7. 사용자 제공 PDF를 읽기 전용으로 분석했다. 좌석 번호는 숫자-숫자 형태의 PDF 텍스트 단어로 확인했다.

| 배치 형태 | 문서 표기 좌석 수 | PDF 좌석 텍스트 | 블록 연결 후보 | 미매칭 | 자동 검사 |
| --- | ---: | ---: | ---: | ---: | --- |
| 기본 프로시니엄 | 608 | 608 | 608 | 0 | 통과 |
| 3분할(小) 208석 | 208 | 208 | 208 | 0 | 통과 |
| 3분할(小) 224석 | 224 | 224 | 224 | 0 | 통과 |
| 3분할(大) 384석 | 384 | 384 | 384 | 0 | 통과 |
| 돌출형 | 832 | 832 | 608 | 224 | 실패 |
| 로드형 | 560 | 560 | 0 | 560 | 실패 |
| 아레나형 | 944 | 944 | 608 | 336 | 실패 |

숫자는 이 추출기를 동일한 7개 파일에 실행해 얻은 **기계적 후보 수**다. 좌석별 수작업 전수 대조를 하지 않았으므로 '608/608'을 인식 정답률 100%라고 표현할 수 없다. 다른 공연장에서의 일반화도 검증하지 않았다.

기본 프로시니엄 배치의 후보 집계는 A~J블록 각 56석, FOH 48석이다. 208석 배치는 A·B 각각 56석, C·D 각각 48석이다. 208석과 224석을 비교하면 208석의 C블록에서는 6·7행의 5~8번, D블록에서는 6·7행의 1~4번이 빠져 있어 총 16석 차이가 난다. 이는 두 PDF에 표시된 좌석의 비교이지 실제 설치 상태의 증거는 아니다.

실패한 세 배치에는 무대 측면·후면 좌석과 수직 또는 다른 위치에 배치된 블록 라벨이 있다. 현재 코드는 수평 라벨 바로 아래의 표 상단 선분만 탐색하므로 이를 연결하지 못한다. 미매칭을 다른 블록에 억지로 할당하지 않는 것은 의도적 동작이다.

## 테스트 및 검증 범위

- 합성 벡터 PDF에서 반복 좌석 번호의 블록 분리
- 상단 경계선이 없는 블록의 자동 미매칭 처리
- 문서 표기 좌석 수와 추출 개수 불일치 감지
- 다중 페이지 PDF의 명시적 거부

합성 fixture 기반 표적 단위 테스트 4개가 실행돼 통과했다. 실제 PDF는 저장소 테스트 fixture나 CI에 포함하지 않는다.

## 데이터·서비스 제약

공식 웹사이트에서 공개된 PDF라도 재배포 또는 ML 학습 허용이 확인된 것은 아니다. 사용자가 확보한 사본은 로컬 분석에만 사용하고, 제3자 공유·학습 데이터셋 구성 전에는 적용되는 이용 조건을 별도로 확인한다.

PDF 텍스트 위치는 의자의 물리적 중심이 아니다. 무대 폭·좌석별 단차·가림 구조물 등의 실측 정보가 없으므로 현재 `convertPlan` 경로에 그대로 넣지 않는다. 기존 제품 코드는 변경하지 않았으며 유료 클라우드·VLM·OCR 호출도 수행하지 않았다.

PyMuPDF는 AGPL/상용 라이선스 체계를 제공한다. 비공개 상용 제품에 결합하기 전에 라이선스 적합성을 검토해야 한다.

## 2026-10-23 후속 실험: PDF 레이아웃과 JPEG CV·OCR

기존 입력 준비와 baseline 재현을 반복하지 않고 저장된 로컬 결과와 개선 추출기를 비교했다. 실행 기록은 2026-10-22 17:47 UTC(2026-10-23 KST)이며, 환경은 Python 3.13.15, PyMuPDF 1.26.7, Pillow 13.0.0, NumPy 2.5.4, OpenCV 5.0.0, Tesseract.js 7.0.0이다. 기존 `extract_seats.py`는 보존했고 개선 구현은 `extract_layout.py`에 있다.

### PDF 7개 수정 전후 비교

| 배치 | 좌석 텍스트 | 기존 연결 | 기존 미매칭 | 개선 연결 | 개선 미매칭 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 프로시니엄 | 608 | 608 | 0 | 608 | 0 |
| 아레나 | 944 | 608 | 336 | 944 | 0 |
| 돌출형 | 832 | 608 | 224 | 832 | 0 |
| 로드형 | 560 | 0 | 560 | 560 | 0 |
| 3분할(大) | 384 | 384 | 0 | 384 | 0 |
| 3분할(小) 224 | 224 | 224 | 0 | 224 | 0 |
| 3분할(小) 208 | 208 | 208 | 0 | 208 | 0 |

총 3,760개 텍스트 후보를 연결했고, 기존에 연결된 모든 좌석 ID와 반올림한 텍스트 중심 좌표가 유지됐다. 7개 모두 자동 무결성 검사를 통과했지만 **자동 매칭 개수는 정답률이 아니며 실제 인식 정확도는 아직 미측정**이다.

실패 원인은 수평 라벨 아래쪽만 찾던 기존 규칙이었다. 개선 방식은 서로 닿는 벡터 경계를 묶고, 텍스트 방향에 맞는 인접 경계의 범위로 블록을 연결한다. 무대 측면의 회전 라벨과 아레나 후면의 아래쪽 라벨을 처리하며, 208석 배치의 연결된 경계와 일부 좌석 누락도 그대로 남긴다. 파일명별 정답표나 공연장 고정 좌표는 사용하지 않는다. 후보 영역이 겹치거나 동일 블록 내 ID가 중복되면 미매칭으로 남긴다. 임의 각도 회전, 끊어진 선, 복잡하게 공유된 경계는 여전히 한계다.

### JPEG 첫 CV·OCR 결과

두 원본은 CMYK JPEG다. 극장 2는 1754×2550 px, 극장 3은 1754×2480 px이며 작업용 RGB 사본을 사용했다. PDF처럼 직접 추출할 수 있는 구조화된 텍스트는 없다.

| 자료 | 회색 도형 후보 | 번호 OCR 채택 | 좌석 ID 연결 후보 | 미매칭 도형 | 파란 영역 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 극장 2 | 506 | 465 | 366 | 140 | 6 |
| 극장 3 | 244 | 220 | 202 | 42 | 2 |

OpenCV의 중성 회색 마스크·윤곽선·대표 사각형 크기로 도형을 찾고, 확대·반전한 개별 숫자 crop을 로컬 영어 OCR로 읽었다. 같은 행의 양쪽 라벨이 일치할 때 연결하며 BOX 영역은 연속된 세로 좌석열로 제한한다. 제품 `src/ocr.js`는 변경하지 않았다.

극장 2의 범례는 일반판매석 466, OP석 40, 휠체어석 6으로 총 512석이다. 회색 후보에는 OP석도 포함된다. 극장 3은 **일반판매석 244 + 휠체어석 4 = 총 248석**이다. 검출된 파란 영역 2개를 휠체어석 2개로 해석하거나 범례 숫자에 맞춰 임의로 4개 객체로 나누지 않았다. 접근성 영역은 개별 일반 좌석과 분리하며, 영역별 좌석 수는 확정하지 않았다.

일부 한 자리 숫자 6·9와 I행, 극장 2의 O·R행 및 OP 라벨이 미해결로 남았다. 전체 이미지 OCR은 인접 숫자를 긴 문자열로 합치기도 한다. 초기 구현에서 BOX 연결이 아래층까지 이어지는 문제가 발견되어 연속 좌석열의 간격으로 범위를 제한했고 회귀 테스트로 보존했다. 최종 결과에 중복 ID는 없지만 정답 연결을 보증하지 않는다. 보수적인 간격 검사에서는 누락 후보가 0개였으며, 이를 검출 재현율 100%로 해석하지 않는다.

### 검증 및 수동 검토

합성 PDF·이미지·평가 테스트 24개가 통과했다. 원본 자료를 테스트 fixture로 넣지 않았다. 커밋 준비 시 별도 실험 worktree에서 같은 24개 테스트와 JavaScript 구문 검사를 다시 실행했다. 이전 로컬 실험에서는 검토 페이지의 표본 로딩, 필드 적용 범위, 편집 유지, JSON 내보내기·불러오기, crop 로딩을 headless 브라우저로 검증했다. 이번 Git 정리에서는 원본 실험과 브라우저 검증을 다시 실행하지 않았다.

블록·행별 가장자리와 중앙, OCR 미해결 영역, BOX 좌석과 접근성 영역을 포함한 수동 검토 표본 550개를 준비했다. 아직 모두 미검토다. 도형 검출, 좌석명, 블록·행·번호 연결, 잘못된 자동 연결, 미매칭·수정 항목을 구분한다. 위치 오차는 PDF 텍스트 중심의 pt와 이미지 도형 중심의 px를 분리한다. PDF 개별 좌석 도형 자체를 검출한 것으로 평가하지 않는다.

평가기는 검토 완료된 해당 항목만 분모에 넣으며 미검토·불확실 항목은 성공이나 실패로 계산하지 않는다. 목적 표집이므로 전체 도면의 정확도를 추정하지 않는다. 검출 재현율을 계산하려면 후보 crop 외에 독립적으로 주석한 완전한 영역별 정답 목록이 필요하다. **실제 인식 정확도와 검출 재현율은 미측정 상태다.**

JSON·CSV·표시 이미지·검토 UI·상세 HTML은 로컬 `output/phase-abc/`에 생성한다. 입력, 출력, 개인 경로가 들어가는 로컬 매니페스트, 생성 이미지·캐시는 Git에 포함하지 않는다. 이 문서에는 자료를 재배포하지 않는 집계와 한계만 기록했다. 제품 UI·Three.js·변환 엔진은 변경하지 않았고, 좌표를 공연장의 미터 단위 위치로 취급하지 않는다. 유료 API나 딥러닝 학습을 사용하지 않았다.
