## 바로 실행

Node.js 20.19+ 또는 22.12+를 설치한 후:

```sh
git clone https://github.com/liminal-cipher/sightcheck-ai.git
cd sightcheck-ai
npm install --package-lock=false
npm run build
npm run demo
npm start
```

브라우저에서 **http://127.0.0.1:4173/operator.html**를 엽니다. `npm run demo`는 가상 공연 예시를 서버 저장소에 추가하며 기존 같은 이름의 시연 자료는 유지합니다. 기존 좌석 비교 화면은 `/index.html`에서 확인할 수 있습니다. 이 주소는 서버를 실행한 PC에서만 접근할 수 있으며 배포된 웹사이트 주소가 아닙니다. 저장소가 비공개이면 clone에도 GitHub 인증이 필요합니다.

Windows에서는 `npm run build` 후 이 폴더의 `start.ps1`을 PowerShell로 실행하면 빌드된 앱을 로컬에서 엽니다. Node.js가 필요합니다. Codex에 포함된 Node도 자동으로 찾습니다. 기본 포트가 다른 프로그램에 사용 중이면 4173~4183 중 빈 포트를 선택합니다. 실행 파일과 서버는 이 PC 안에서만 동작합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

다른 환경에서 이미 빌드된 파일 실행: `node scripts/serve.mjs`. 포트 변경: PowerShell에서 `$env:SIGHTCHECK_PORT='4180'` 설정 후 실행합니다. HTML을 파일로 직접 열면 모듈·OCR worker가 동작하지 않으므로 HTTP 서버를 사용하세요.

코드를 수정할 때:

```sh
npm install --package-lock=false
npm run prepare:ocr
npm run dev
npm test
npm run build
```

저장소에는 `pnpm-lock.yaml`이 있습니다. 잠긴 의존성으로 설치하려면 위 설치 명령 대신 `pnpm install --frozen-lockfile`을 사용하세요. npm 대안은 같은 의존성 트리를 보장하지 않으며, npm lockfile이 없으므로 `npm ci`는 사용할 수 없습니다. `public/ocr`의 worker·WASM·영문 모델은 `prepare:ocr` 또는 `build`가 설치된 패키지에서 복사합니다. 인식할 때 사진을 외부 AI 서버에 전송하지 않습니다. 글꼴은 온라인에서 Noto Sans KR을 요청하며, 오프라인에서는 시스템 글꼴을 사용합니다.

## 운영자 화면에서 게시하기

1. `/operator.html`에서 가상 도입 시연 공간과 공연을 선택합니다. 공간·배치·현장 대조·게시 단계로 이동할 수 있습니다.
2. 공연을 복제하거나 좌석 바닥높이, 관람 대상, 설치물 위치·크기·회전을 수정하고 저장합니다.
3. 실제 적용에서는 같은 좌석·배치·관람 대상·눈높이의 사진과 담당자의 대조 기록을 등록합니다. `reviewed` 게시에는 공개할 좌석마다 조건에 맞는 기록이 필요합니다. 사진이 없는 가상 예시는 `demo` 게시로 구분합니다.
4. 게시 단계에서 관객 링크와 연동 예시를 엽니다. 예매 좌석 버튼을 누르면 iframe 뷰어의 해당 좌석으로 이동합니다. 실제 예매 재고·결제는 연결하지 않았습니다.
5. 구조물 변경이나 게시 중지 후에는 기존 공개 링크를 차단합니다. 운영 데이터와 비공개 사진은 Git에 포함하지 않습니다.

기본 실행은 루프백에서만 접근합니다. 외부 서버에서 실행하려면 24자 이상의 `SIGHTCHECK_ADMIN_TOKEN`, HTTPS 프록시와 별도 운영 검토가 필요합니다. 운영자 UI에는 원본 토큰을 커밋하지 않고 실행 환경으로 제공하세요. 저장소는 서버 파일 기반이며 다중 고객 상용 운영 환경은 아닙니다.

아래 시연과 2026.10.01 검증 기록은 기존 좌석 비교·도면 변환 화면에 관한 설명입니다.

## 3분 시연 순서

**새 도면 변환 흐름:** 공연장 관리 → 변환 예시 불러오기 → 기준점·좌표·단차·구조물 검토 → 사용 권한/검토 체크 → 변환 API 실행 → 변환 모델로 시야 보기 → C3·D3 비교. 실제 도면은 좌석 문자 후보를 추출한 뒤 누락을 보완하고 실측 높이·구조물을 입력합니다. 사진만 올리면 정확한 공간이 자동 완성되는 서비스는 아닙니다.

1. **가림 차이 체험**을 누릅니다. C3와 D3를 같은 60° 화각과 눈높이로 비교합니다. 기본 치수에서 가리지 않은 표본은 69%와 100%, C3의 무대 하단 표본은 20%입니다. 이는 가상 영역의 표본 계산이며 실제 좌석 평점이나 무대 면적 비율이 아닙니다.
2. **공간 전체**로 바꿔 20석·단차·전면 난간의 위치를 살펴봅니다. **좌석 시점**으로 돌아가 드래그·방향키로 둘러보고 눈높이와 가린 표본 표시를 조절합니다.
3. **A2**를 고른 뒤 **라이브**로 바꿉니다. 촬영 타워가 추가되면서 기본 모델의 표본 비율이 100%에서 84%로 바뀝니다.
4. **공연장 관리 → 예시 도면 불러오기 → 좌석 문자 인식**을 누릅니다. 실제 로컬 OCR이 A1~D5 20개를 추출합니다. 외부 이미지에서는 누락·오인이 가능하며, 운영자가 순서와 이름을 수정합니다.
5. 난간 높이를 **1.0m → 0.4m**로 저장합니다. C3의 표본 비율이 100%로 바뀌며 새로고침 후에도 치수와 모델 버전이 유지됩니다. 기본 모델은 **가상 모델로 복원**으로 돌아옵니다.
6. **실사진과 대조**에서 이미지를 첨부하고 촬영 조건과 대조 내용을 남깁니다. 모델·좌석 이름·공연 배치·눈높이가 바뀌면 이전 기록은 재대조 상태입니다. 대조 완료 표시는 운영자 기록이며 자동 정확도 인증이 아닙니다.
7. **시야 이미지 저장**을 누르면 가상 모델 안내·좌석·버전·눈높이가 포함된 PNG를 받습니다. **좌석 선택 내용 보기**는 비교 메모를 제공합니다. 운영자가 HTTP(S) 예매 주소를 등록한 경우에만 외부 페이지로 연결합니다.

## 구현 범위

| 항목 | 구현 |
| --- | --- |
| 3D | 공유 모델·좌석 InstancedMesh, 초기 20석 또는 도면 변환 1~300석, 무대 2종, 좌석 눈높이 카메라, 회전·공간 보기 |

| 저장 | 브라우저 localStorage, 모델 JSON import/export, 입력 검증, 사진 첨부·대조·이전 조건 표시 |

초기 schemaVersion 1 모델은 **4행 × 5열**의 가상 예시입니다. 새 schemaVersion 2는 검토한 축척 도면의 임의 평면 좌표·바닥 높이·구조물을 1~300석 모델로 변환합니다. OCR은 영문·숫자 문자 후보를 읽으며 좌석 중심·높이를 운영자가 확인합니다. 원근 사진·축척 없는 예매 좌석도만으로 정확한 3D를 만들지는 않습니다.

Blender는 런타임 의존성이 아닙니다. 현재 좌석·벽·무대·인체 기준 자산을 코드로 제작했습니다. 현장 모델을 확장할 때 Blender로 만든 glTF 자산·베이크 텍스처를 표시층에 붙일 수 있지만, 가림 판정용 구조물과 좌표·실루엣·모델 버전을 맞춰야 합니다.

## 개정 검증 결과 (2026-10-01)

- Node 테스트 10개 통과. 가상 도면의 20석 좌표·층 높이·뮤지컬/라이브 가림 계산을 기존 실측 예시와 대조하고 회전/이동 도면, 임의 3석, 오류 입력, HTTP API를 확인했습니다. 실제 공연장 정확도 실적이 아닙니다.
- Chrome에서 도면 예시 → 검토 → 실제 API 요청 → 모델 적용 → C3/D3 비교를 확인했습니다. 69%/100% 및 C3 하단 표본 20%가 동일합니다. 20석 모델 JSON 약 2.3KB는 좌표·구조물 데이터 크기이며 전체 앱·OCR 모델 크기가 아닙니다.
- 새 축척 예시 `engine-plan.png`의 로컬 OCR은 20개 중 16개 후보를 추출했습니다. 높이·구역·행은 추정하지 않으며 비워 둡니다. 바닥 높이를 입력하지 않은 결과는 변환을 거부합니다. 아래 초기 예시 OCR 20개와 다른 입력입니다.
- 입력 수정 시 검토 체크를 해제하고 이전 API 결과 적용을 비활성화합니다. 3석으로 재변환해 표시·계산과 선택 상태를 확인했습니다. 같은 좌석명이 남아 있으면 모델 갱신 후에도 선택을 유지합니다.
- 변환 모델의 390px/320px 화면에서 가로 넘침이 없고, 비교 화면을 확인했습니다. 데스크톱 Chrome의 뷰포트 검사이며 실제 모바일 기기의 성능 검증은 아닙니다.
- 클라이언트와 Node API의 실행용 번들을 빌드했습니다. 클라이언트 기본 JS가 약 603KB(압축 약 156KB)로 Vite의 500KB 청크 경고가 남습니다. 사진 재구성 모델을 탑재한 가벼운 앱이라는 의미가 아닙니다.
- 실행 ZIP을 별도 폴더에 풀어 `node_modules` 없이 Node 서버의 화면·health·20석 변환·C3 시야 API를 확인했습니다. ZIP은 OCR WASM·언어 모델·문서·소스까지 포함해 약 40.8MB입니다. 압축을 풀고 `start.ps1` 또는 `node scripts/serve.mjs`로 실행합니다.
- 개정 기획안은 출처·AI 활용 표시·가상 시제품 그림을 포함해 A4 3페이지입니다. 본문 12pt, 줄 간격은 12pt의 160%인 고정 19.2pt로 설정했고 Word PDF 출력 후 전 페이지를 확인했습니다.

- Node 테스트 5개 통과: 발코니 앞/뒷줄 가림, 공연별 타워 영향, 난간·눈높이 변화, 잘못된 모델/URL 거부, OCR 후보 정렬.
- 실제 예시 PNG OCR 20개 추출: `node scripts/check-ocr.mjs`. 처음 사용한 글꼴에서는 18개만 추출돼 선명한 예시로 보정했으며, 실제 도면의 인식률을 보장하지 않습니다.
- Chrome 브라우저 조작: 좌석·비교·공간 보기·무대 변경·도면 OCR·저장/새로고침 복원·누락 좌석 저장 거부·사진/메모 검증·사진 조건 변경 표시·예매 메모 확인.
- PNG 실제 생성·다운로드 확인: 별도 Chrome/Playwright 컨텍스트에서 `sightcheck-C3.png` 다운로드 성공(실패 값 없음). agent-browser의 Windows 다운로드는 일반 이미지에서도 취소되어 이 항목을 별도로 검증했습니다. 결과 파일은 `screenshots/export.png`입니다.
- 1440×1000, 390×844, 320×800 레이아웃 확인. 390px·320px에서 가로 넘침 없음.
- 자동 접근성 검사 axe 4.12.1: 390px 기본 화면 위반 0개. 캔버스 위 안내 문구의 배경 대비는 자동 검사 미확정 1개이며 사람 검토가 필요합니다.

스크린샷: `screenshots/desktop.png`, `compare.png`, `overview.png`, `mobile.png`. 이 결과는 데스크톱 Chrome 검증이며 실제 모바일 기기의 GPU·메모리·느린 네트워크 성능 실적은 아닙니다.

## 실서비스 전에 필요한 작업

실제 공연장 실측·자료 사용 허락, 대표 좌석 실사진 검증, 다중 운영자 계정·권한과 백업·운영 체계, 티켓 플랫폼 계약 및 재고·좌석 ID 연동이 필요합니다. 단일 운영자용 서버 파일 저장·검수·게시 흐름은 구현돼 있습니다. 앞사람·기둥·추가 세트 등 실제 가림 객체의 범위를 넓히고 현장 사진과 계산 결과의 오차를 측정해야 합니다. 서버 시야 이미지 렌더링/캐시, 360도 실사진, 사진 복원·Gaussian Splatting·LLM 상담은 이 버전의 구현 범위에 포함되지 않습니다.

제품의 AI 구현은 OCR입니다. 규칙 기반 시야 가이드를 LLM 답변으로 표시하지 않습니다. 업로드 사진에서 치수를 자동 생성하거나 실사진 인증을 주장하지 않습니다. 시제품에는 토큰 기반 운영자 인증이 있지만 사용자 계정·결제·테넌트 격리는 없습니다. 변환/시야 계산 요청은 보관하지 않으며, 운영자 화면에서 저장한 모델·사진·검수·게시 기록은 서버 파일 저장소에 보관합니다.

## 소스 구성과 오픈소스

- `src/model.js`: 모델 검증, 좌석 좌표, 고정 구조물, 광선 교차 계산
- `src/scene.js`: 재사용 자산, 인스턴싱, 공통 renderer, 카메라, PNG 출력
- `src/main.js`: 사용자/운영자 흐름, 사진 대조 기록과 버전 관리
- `src/ocr.js`: 실제 OCR worker와 문자 후보 정렬
- `scripts/prepare-ocr.mjs`: 로컬 worker/WASM/모델 준비
- `src/conversion.js`, `server/api.mjs`: 도면 좌표→경량 모델·카메라, HTTP 입력 검증, 시야 계산
- `src/engine-studio.js`: 입력·OCR·보정·변환·적용 흐름
- `scripts/serve.mjs`: 빌드 앱과 번들된 API를 로컬에서 서비스
- `vite.config.js`, `vite.api.config.js`: 개발 API / 실행용 서버 번들
