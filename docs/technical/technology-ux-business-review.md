# 시야체크 AI 기술 UX BM 검토 노트

이 문서는 제출용 3쪽 기획서의 근거와 확장 설계다. 제휴·가격·성능은 검증 전 가설이며, 계약이나 실측 성과를 뜻하지 않는다. [공식 공고문](https://www.kfict.or.kr/upload/comm/178894596563685.pdf)의 접수 마감은 **2026년 10월 2일**, 제출물은 **표지 포함 A4 3쪽 이내의 PDF**다. 참가신청서(동의·서약 포함)는 별도로 필요하며, 완성한 화면 시안은 선택 보조자료로 제출할 수 있다. 기획 분야에는 **누가·언제·얼마나 자주 사용하는지**가 필수다.

## 핵심 판단

- 문제의 핵심은 3D 공간 탐험이 아니라 **고가의 좌석 두 개 중 어느 쪽을 살지 결정하는 순간**이다.
- 첫 구매 고객은 중형 공연장에서 지정좌석 공연을 여러 회차 운영하는 **공연 기획사와 공연장 운영사**다. 관객은 무료로 쓴다.
- 제품의 현재형은 공식 예매처에 붙는 좌석 시야 비교 페이지·위젯이다. 장기적으로 예약 플랫폼을 운영할 수 있지만, 좌석 재고·결제·임시 점유는 제휴 없이는 가능하다고 쓰지 않는다.
- 경쟁 우위의 가설은 멋진 3D 자체가 아니라 **공연별 세트 변경을 싼 비용으로 반영하는 제작 도구와 검증 데이터**다.
- 공모전 주제에 맞춰 **공연 판매 기간 매일 오전 좌석 문의와 배치 변경을 확인하는 예매·고객지원 담당자**를 일상 사용 주체로 명시한다. 관객 사용은 예매 시점에만 일어나는 저빈도 경험임을 숨기지 않는다.

## 예약 경험 UX

1. 공연 선택: 작품·회차·예산을 먼저 고른다. 공연별 무대 버전이 바뀌면 이전 자료를 그대로 쓰지 않는다.
2. 좌석 선택: 2D 좌석도는 주 화면으로 유지한다. 가격·잔여석은 공식 예매처에서 받은 값만 표시한다. 사용자는 후보 두 좌석을 비교함에 담는다.
3. 비교: A/B 좌석의 눈높이 3D 시점과 가림 원인, 실제 사진 여부, 촬영일·검증일을 나란히 보여준다. 3D 조작은 선택 사항이며, 약한 기기에서도 정적 미리보기 이미지를 제공한다.
4. 예약: 공식 예매처의 해당 공연·회차로 이동한다. 좌석까지 딥링크가 허용되지 않으면 좌석 ID를 복사하거나 다시 선택하도록 안내한다. 가용 좌석이 바뀌면 선택 확정을 보장하지 않는다.
5. 운영자 화면: 기본 공연장 자료 업로드 → 기준 치수 입력 → AI 추출 결과 수정 → 공연별 무대 배치 추가 → 대표 좌석 검증 → 승인·게시. 승인 뒤 구조나 무대가 바뀌면 버전이 올라가고 해당 검증 표시가 재심사된다.
6. 일일 운영: 공연 판매 기간 매일 오전 담당자가 신규 좌석 문의와 배치 변경 알림을 확인한다. AI는 승인된 좌석 모델·사진·공연 버전만 검색해 답변 초안을 만들고, 근거가 없는 질문은 '자료 부족'으로 보내 사람의 확인을 요청한다. 답변은 자동 공개하지 않는다.

디자인 원칙: 좌석도가 구매의 중심이고 3D는 판단을 돕는 레이어다. 3D 전체화면 진입을 강제하지 않는다. 가격·가림·검증 상태는 색상만으로 구분하지 않고 문구·아이콘을 함께 쓴다. 모바일에서는 좌석도 위, 비교 패널 아래의 시트 형태로 배치한다. ‘검증되지 않은 자리’에 정밀한 수치 점수를 표시하지 않는다.

별도 파일 `시야체크_AI_예약_UX_개념도.png`는 이 A/B 비교 흐름의 **가상 데이터 시안**이다. 실제 경기장·공연장 모델, 실시간 가격·재고, 실측 시야 또는 제휴를 나타내지 않는다. 공식 공고에서 허용한 선택 시각자료 ZIP으로도 묶어 두었다.

`oh-my-design`에는 동명이 계열이 있다. [3x-haust/oh-my-design](https://github.com/3x-haust/oh-my-design)은 UI 제작의 검토·렌더링 프로세스이며, [kwakseongjae/oh-my-design](https://github.com/kwakseongjae/oh-my-design)은 디자인 시스템 참고 자료다. 둘 다 좌석 예매 컴포넌트 자체가 아니다. [react-seat-picker](https://github.com/roggervalf/react-seat-picker)는 간단한 좌석 선택 컴포넌트의 참고 후보이고, [SeatLayer 예제](https://github.com/seatlayer/seatlayer-react-example)는 임시 점유·결제 인계 흐름의 참고 자료지만 좌석맵 엔진은 별도 호스팅 서비스다.

## 3D 제작 기술 비교와 권장 조합

| 입력 | 결과 | 장점 | 제품상 한계 | 권장 역할 |
|---|---|---|---|---|
| 좌석도 스크린샷만 | 행·열·구역 후보 및 규칙 기반 3D | 자료 접근이 쉬움 | 단차·난간 높이·원근 깊이를 알 수 없음 | 개념 시안 또는 운영자 초안 |
| 겹치는 현장 사진 여러 장 | VGGT/COLMAP의 카메라 위치·점군·깊이 | 공간 형태를 더 가깝게 파악 | 반복되는 좌석 패턴, 어두운 조명, 가려진 구조에 취약 | 공간 초안 |
| 사진 + 기준 치수·도면 | 치수 보정된 구조물 메시 | 좌석 시야 가림 계산 가능 | 관리자의 검수 비용이 남음 | **판정용 기준 모델** |
| 사진 + Gaussian Splatting | 사실적인 새로운 시점 이미지 | 관객 몰입과 신뢰를 높임 | 누락된 뒷면·보이지 않는 영역을 정확히 보증하지 못함 | **표현층**, 가림 판정에는 단독 사용 금지 |

권장 제작 파이프라인: (1) 운영자에게 좌석 배치도와 좌석 간격·단차·난간 높이·무대 위치 등 기준 치수를 받는다. (2) PaddleOCR로 행·열을 읽고 SAM 2로 운영자가 지목한 구조물의 윤곽을 얻는다. (3) Three.js에서 [InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html)로 반복 좌석을 배치하고 난간·무대는 간단한 도형으로 모델링한다. (4) 공통 모델에서 좌석 카메라만 이동해 시야를 보여주고 무대 핵심 영역까지 광선을 쏴 가림을 판정한다. (5) 재질·음영을 보강하고, 성능이 낮은 기기에만 요청된 좌석의 이미지를 제공·캐시한다. (6) 대표 좌석 실제 사진과 대조해 ‘검증’ 배지를 발급한다. 다각도 사진·치수가 확보된 공연장에만 VGGT/COLMAP 공간 복원이나 Blender 자산 편집을 후속 적용한다.

**2D 이미지 + Three.js의 정확한 역할:** 좌석도 스크린샷은 구역·행·열의 **평면 좌표 초안**이다. 실제 좌석 간격·열 단차·난간 높이·무대 치수를 별도로 넣어야 3D 시야 판정을 할 수 있다. 블록 프리비즈처럼 반복 좌석과 장애물을 Three.js 도형으로 만들면 초기 제품에 Blender가 필수는 아니다. 다수의 좌석을 개별 메시로 그리기보다 InstancedMesh로 묶어 렌더링 비용을 줄인다. [Blender의 이미지 평면 기능](https://docs.blender.org/manual/de/4.2/modeling/meshes/import_images_as_planes.html)은 텍스처를 붙이는 기능이지 사진을 정확한 입체 공간으로 변환하는 기능은 아니다.

시연 우선순위는 **좌석도 1장 + 실측 치수 + Three.js 구조 모델 + 실제 좌석 사진 검증**이다. 광범위한 사진 측량, Blender의 정교한 자산 제작, Gaussian Splatting은 자료가 확보된 다음 단계다. 이 조합이 제작 범위와 시야 정확도를 통제하면서도 공연별 무대 변경을 보여주기에 가장 적합하다.

### 이미지 모델과 360도 출력의 사용 조건

- **권장 기본 화면:** 공연장 공통 모델을 읽고 좌석 카메라만 이동한다. 전방 정적 시야 이미지는 성능이 낮은 기기에서 선택 좌석을 요청할 때 생성·캐시하는 보완 경로다. 모든 좌석의 이미지를 미리 만들지 않는다. 상세한 최적화·검증 설계는 별도 파일 `시야체크_AI_권장_3D_구성.md`에 정리했다.
- **선택형 360도:** 관객이 주변 난간·통로·측면을 확인할 필요가 있을 때만 파노라마를 제공한다. Three.js는 [equirectangular 파노라마 표시](https://threejs.org/examples/webgl_panorama_equirectangular.html)와 장면의 [큐브 카메라 캡처](https://threejs.org/docs/pages/CubeCamera.html)를 지원한다. 파노라마는 한 자리에서 회전해 보는 경험이며, 자리를 옆으로 움직이는 시차·가림 변화는 재현하지 못한다.
- **가벼워지는 조건:** 운영자가 게시할 때 파노라마를 미리 렌더링·압축해 두면 구매 시점의 브라우저는 복잡한 장면을 매번 그릴 필요가 없다. 반면 좌석 수 × 공연 배치 버전만큼 이미지가 늘고, 고해상도 360도 텍스처의 전송·메모리 비용이 생긴다. 간단한 도형 장면은 Three.js가 직접 그리는 편이 더 가벼울 수 있으므로 실제 기기에서 측정한다.
- **이미지 생성 AI의 역할:** 벽·재질·조명 등 외관을 꾸미거나 가상 시연 자료를 만드는 데 쓴다. 생성형 이미지가 난간 위치·무대 가림을 바꾸면 구매 정보가 틀리므로, 검증된 기하 구조의 마스크와 가림 표시를 고정하고 생성 화면은 '시각화 예시'로 표시한다. 단일 이미지의 360도 확장은 관찰되지 않은 영역을 새로 만들어야 하므로 정확한 좌석 시야 증거가 아니다. [CVPR 2025 파노라마 생성 연구](https://openaccess.thecvf.com/content/CVPR2025/html/Zheng_Panorama_Generation_From_NFoV_Image_Done_Right_CVPR_2025_paper.html)도 좁은 시야의 이미지를 360도로 확장하는 문제를 별도 생성 과제로 다룬다.

**보여주기용 기술과 계산용 기술을 분리**한다. 한 장 이미지 기반 생성 모델은 뒤편이나 안 보이는 난간을 만들어낼 수 있으므로 실제 좌석 시야의 근거로 쓰지 않는다. [Unreal Home Wizard](https://github.com/amirmushichge/unreal-home-wizard)는 실내 사진 기반 작업 흐름을 보여주지만 정밀 디지털 트윈을 보장하지 않는다. [StadiView](https://github.com/thebuggeddev/football-stadium)는 좌석 클릭 UX가 훌륭한 시연이지만 가상의 구장·가상 예매 데이터이며 비상업 라이선스다. 코드나 명칭을 제품에 가져오지 않는다.

기술 출처: [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR), [SAM 2](https://github.com/facebookresearch/sam2), [VGGT](https://github.com/facebookresearch/vggt), [COLMAP](https://github.com/colmap/colmap), [Blender](https://www.blender.org/features/), [Three.js Raycaster](https://threejs.org/docs/pages/Raycaster.html), [Nerfstudio Splatfacto](https://github.com/nerfstudio-project/nerfstudio/blob/main/docs/nerfology/methods/splat.md), [SuperSplat](https://github.com/playcanvas/supersplat). VGGT의 코드·모델은 전용 라이선스를 확인해야 하며 원본 체크포인트는 비상업용, 별도 신청하는 `VGGT-1B-Commercial`만 상업 이용을 허용한다고 프로젝트가 밝힌다.

## 타깃 BM 제휴 순서

1. **첫 고객:** 2층 난간·측면 구조물 등 시야 차이가 있고 동일 공간에서 여러 회차를 파는 중형 공연장의 기획사/운영사. 한 공연의 높은 제작비를 여러 회차에 나눠 회수할 수 있다. 반대로 1회성 소형 공연은 고객의 지불 여력이 낮을 수 있다.
2. **돈을 내는 이유:** 기존 문구 안내·문의 대응·대표 좌석 사진 제작에 투입하는 작업을 줄이고, 공개하기 어려운 시야제한석의 판단 근거를 제공한다. 매출 상승·환불 감소는 가설이므로 먼저 측정한다.
3. **첫 과금:** 공연장 기본 모델 최초 제작비 + 공연별 무대 배치·검증 갱신비. 특정 가격은 사전 인터뷰 전 확정하지 않는다. 월 구독이나 판매 수수료는 반복 운영 또는 공식 거래 데이터가 확보된 뒤 검증한다.
4. **제휴 후보:** [NHN LINK의 회사 소개](https://www.ticketlink.co.kr/introduction/company)는 티켓링크 예매 채널과 현장 운영 서비스를 소개한다. 따라서 시범 협업을 제안할 만하지만 확약된 제휴는 없다. [네이버 예약 사업자센터](https://help.naver.com/service/11712/category/1048)는 회차형 좌석 배치도 제작 절차를 안내한다. NOL 티켓·YES24 티켓 등도 향후 공식 판매 채널 연동 후보일 뿐, 공개 재고·결제 API가 있다는 근거는 확인되지 않았다. 제휴 전에는 링크로만 연결한다.

첫 판매 경로는 대형 플랫폼 제휴 요청보다 **자료 사용 권한을 직접 줄 수 있는 공연장·기획사 한 곳**이다. ① 한 공연장의 20좌석·두 무대 배치로 유료 또는 원가 보전형 파일럿을 제안하고 ② 시야 자료 제작 시간과 문의 답변 시간을 측정한 뒤 ③ 공연장 기본 모델 재사용 계약을 협상한다. 이 증거가 생기면 예매 플랫폼에 공식 위젯 연동을 제안한다. 제작비가 데이터 촬영·수동 보정 인건비를 덮지 못하면 과금 모델이 성립하지 않으므로, 좌석당 제작 시간과 다음 공연 배치 갱신 시간을 함께 기록해야 한다. 운영자의 지불의사는 실제 고객 인터뷰 전까지 가정이다.

## 경쟁과 차별화의 실제 범위

[3D Digital Venue](https://3ddigitalvenue.com/)는 이미 3D 좌석 시야와 판매 포털을 제공하므로 ‘세계 최초 3D 좌석 보기’라고 쓰면 안 된다. [A View From My Seat](https://aviewfrommyseat.com/)는 실사 좌석 사진을 제공한다. 국내 [티켓링크의 시야제한석 안내 사례](https://www.ticketlink.co.kr/help/notice/65420)는 실제로 좌석 가격과 가림 원인을 세분화하고 있으나 설명은 텍스트 중심이다. 제품의 가능성은 중형 공연장에 맞는 저비용 제작 도구, 공연별 변경 갱신, 좌석별 실사 검증 상태, 예약 화면 안에서의 즉시 비교를 하나의 흐름으로 묶는 데 있다.

## 검증 설계와 남은 위험

- **시야 정확도:** 공연장 한 곳에서 대표 좌석 20개, 무대 배치 2개를 정한다. 실제 사진을 기준으로 가림 유형을 독립 평가자가 분류하고, 예측과 일치하는 비율을 기록한다. 검증 전에는 가림 정도를 확정 수치로 표시하지 않는다.
- **구매 경험:** 이용자에게 평면 좌석도만 제공한 경우와 시야 비교 화면을 제공한 경우를 비교한다. 결정 시간, 선택 확신도, 구매 후 기대 불일치 여부를 측정한다.
- **구매 고객:** 공연 기획사·운영자 5곳 이상과 인터뷰해 현재 시야 안내에 드는 작업·문의량·자료 권한을 파악하고, 1곳에 유료 파일럿을 제안한다. 이 수치는 테스트 목표이지 완료 실적이 아니다.
- **일일 사용성:** 담당자가 공연 판매 기간에 매일 실제로 열어 볼 이유가 있는지 검증한다. 좌석 문의의 건수·반복 질문 비율·답변 시간·재확인 횟수를 최소 2주 관찰하고, 모델 갱신이 드문 날에도 운영 도구를 쓰는지 확인한다. "매일 사용"은 현재 실적이 아니라 제품 가설이다.
- **운영상 위험:** 무대 세트가 늦게 확정되면 사전 시뮬레이션의 정확도가 떨어진다. 공연 버전 승인 전에는 ‘추정’으로 보이고 변경 시 재검증한다.
- **제출 주제 적합성:** 공식 공고는 ‘매일 반복되는 일상의 불편’과 ‘누가·언제·얼마나 자주’를 강조한다. 공연 관객은 개인별로 매일 쓰지 않으므로 이 아이디어의 **가장 큰 수상 위험**이다. 담당자의 일일 문의 대응을 중심에 놓아도 공모전이 기대하는 대중적 생활 AI보다 B2B 업무 도구로 보일 수 있다. 영화·스포츠 확대를 주장하는 것만으로 이 약점이 해소되지는 않는다. 실제 일일 운영 로그 또는 담당자 인터뷰 한 건만 확보해도 설득력이 크게 높아진다.
